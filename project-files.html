Context

What Part3 does

Architects use Part3 to review documents and coordinate changes during construction.

Contractors send questions and material submissions to architects for review. When a change affects the drawings, architects issue revised sheets. Before Project Files, firms still managed those drawings separately.

What we shipped

Project Files manages drawing sets, individual sheets, and revisions.

Drawings are managed as individual records instead of versions of a single PDF.

Current workflow

Every drawing revision triggered a manual process.

The same handoff repeated whenever architects issued revised drawings.

The change was issued in Part3. The drawings still had to be updated manually. The issued document and the drawing files were maintained separately.

Existing workflow

Customer discovery

The issue went beyond organizing PDFs.

Each drawing had its own number and revision, but file-level storage couldn't show which sheets had changed or which were current.

Product direction

I shifted the product from file versions to individual drawing records.

A set may contain hundreds of drawings, while a new issue changes only a few. If we versioned the whole PDF, architects would still need to work out which sheets had changed.

Each sheet would have its own number, title, revision history, and reference to the document that issued it.

Drawing model

A drawing revision isn't the same as a file version.

The individual-sheet model became the basis for matching revisions and keeping the latest drawings current.

File model versus drawing model

Drawing import

Importing drawing sets

A drawing set can contain hundreds of sheets, each with its own number, title, and discipline. Entering those details manually made importing a set slow and difficult to verify.

I worked with an AI engineer to explore OCR and multimodal extraction for sheet details. We paired automation with a review step so architects could correct the information before it became the basis for tracking revisions.

Import → Extract → Review → Publish

Latest revision

Identifying the latest drawing

Firms can add historical drawing sets after newer revisions are already in use. If upload order determined the latest drawing, importing those records could replace the current set. I used issue dates to protect that distinction, while allowing architects to override it when needed.

  • 01One drawing, multiple revisions

    The sheet keeps one drawing record as new revisions are issued. Its number and discipline stay consistent across versions.

  • 02Each revision has a source

    Revision history shows the issuing document and date, whether it's a Site Instruction, change, or another CA document.

  • 03Current and previous versions stay clear

    The current revision is identified separately from earlier versions, which remain available in the drawing's history.

A-201 Rev 3 → Site Instruction 3.0 → A-201 Rev 4

Drawing history

Revised drawings stay connected to the documents that issued them.

Revised sheets are issued through Site Instructions, Bulletins, and other change documents. Without that connection, architects have to search separate records to understand where a revision came from.

When an architect issues revised sheets through a Site Instruction or other CA document, Part3 adds them to the drawing history and links each revision to its source. The current sheet and the reason for the change stay together.
