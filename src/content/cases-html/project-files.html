Overview

Project Files helps architects manage construction drawings and revisions directly in Part3.

I led the design from early discovery through launch, working with product and engineering to define the product direction and core experience.

Project Files launched as a paid offering, generating over $800K in associated annual revenue.

Hero: drawing register

The problem

Part3 managed construction documents, but not the drawings behind them.

During construction, architects issue documents such as site instructions and proposed changes that often include revised drawings.

While Part3 handled these documents, firms still relied on shared drives and internal servers to maintain their drawing sets. Each revision required someone to replace outdated sheets, organize files, and ensure the team had the latest drawings.

Through customer interviews, I found that the challenge wasn't where firms stored files. It was how they managed drawings as projects changed.

This made me question the original direction of building a general file management system.

Existing workflow

Product direction

From file versioning to individual drawing revisions

I explored different approaches to file organization and versioning, but they didn't account for how drawing sets change during construction.

A single PDF could contain hundreds of sheets, with only a few updated in each issue. Managing versions at the file level would still leave architects responsible for identifying and replacing individual sheets.

I proposed treating each drawing as its own record, with a consistent sheet number, revision history, and reference to the document that issued it.

Working with product and engineering, we defined a model that could support both the initial drawing set and subsequent revisions.

We focused on two priorities: importing drawings at scale and managing revisions through existing construction workflows.

File model versus drawing model

Design

01. Importing drawings at scale

Drawing sets can contain hundreds of sheets, delivered as individual PDFs or one combined file.

I worked with our AI engineer on an import experience that separates combined PDFs into individual sheets. They developed an extraction service using a multimodal AI model to identify drawing numbers and titles.

The main constraint was extraction accuracy.

We gave customers a way to review and correct results before importing, ensuring the drawing information could be used to match future revisions.

Animation: Import → Extract → Review → Publish

02. Connecting revisions to construction documents

Rather than introducing a separate workflow for updating drawings, we used the information already available in Part3.

When an architect issues a site instruction with revised drawings, Part3 can match each sheet to its existing record, preserve the revision history, and update the latest version.

Each revision is also linked to the document that issued it.

The challenge was deciding what should happen automatically and what should remain editable.

Not all revisions arrive in sequence. Older drawings may be uploaded later, and projects can contain multiple drawing packages.

I worked with engineering to define how the latest version would be determined while allowing architects to change it manually when needed.

Detail: drawing revision history

03. Using drawings across Part3

With drawings managed in Part3, architects can access the latest set, compare revisions, and reference drawings in other construction workflows.

We also supported exporting the latest drawings so firms could continue sharing files and maintaining their existing servers.

Outcome

Project Files launched as a paid addition to Part3, generating over $800K in associated annual revenue. Customers have managed more than 100,000 drawings in the product, with the drawing model also supporting workflows such as field reports and AI-assisted features.
